# Map User Journeys

## Goal

Represent how an actor progresses toward an outcome across time, touchpoints, decisions, and channels without inventing experiential detail.

## Method

1. Declare the map mode: `current-state`, `future-state`, or `hypothesis`.
2. Define the actor or role, context, trigger, goal, start and end conditions, scope, channels, and evidence boundary.
3. Map stages, actions, decisions, handoffs, waits, loops, failures, recovery, completion, and post-task activity.
4. Link current-state actions, needs, barriers, pain points, and emotions to approved evidence.
5. Record operational dependencies and moments where the user loses visibility or control.
6. Identify contradictions, role or segment variation, unknown stages, and validation needs.

## Rules

- Do not add emotions, needs, or pain points because they seem plausible.
- Do not present a future-state journey as current behavior.
- A journey is not a task flow or service blueprint; link those artifacts rather than collapsing them.
- Qualitative recurrence does not establish prevalence.
- Keep synthetic fixtures prominently classified.

## Output

Create `../templates/JOURNEY-MAP.md` with traceable stage evidence and explicit mode, confidence, limitations, and next validation needs.
