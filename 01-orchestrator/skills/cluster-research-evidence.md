# Cluster Research Evidence

## Goal

Create a transparent structure for synthesis without allowing convenient themes or source counts to become unsupported user truths.

## Method

1. Verify that each input finding is approved for Define and retain its stable finding and evidence identifiers.
2. Exclude or separately label synthetic, unapproved, superseded, or decision-ineligible inputs.
3. Code findings by behavior, need, obstacle, motivation, context, role, journey stage, consequence, and constraint when the evidence supports those dimensions.
4. Group related findings into clusters and state the relationship that binds each cluster.
5. Record supporting and contradicting findings, negative cases, meaningful outliers, segment or role differences, evidence types, and unanswered questions.
6. State what each cluster can and cannot support before formulating an insight.

## Rules

- Cluster approved findings, not invented observations or decontextualized quotations.
- Do not use the number of notes, quotes, or participants as population prevalence.
- Do not merge findings whose contexts, roles, or causes materially differ.
- Do not remove contradictions to create a cleaner narrative.
- A synthetic workflow fixture may test clustering but must remain ineligible for real product framing.

## Output

Populate `clusters` in `../templates/INSIGHT-SYNTHESIS.md`, including traceability, variation, contradictions, confidence inputs, and inference boundaries.
