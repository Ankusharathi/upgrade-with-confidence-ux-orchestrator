# Skill: Specify Implementation Behavior

## Purpose

Translate approved experience behavior into testable implementation rules and acceptance criteria.

## Method

For every in-scope role, platform, breakpoint, flow, and state, specify entry conditions, data and permissions, hierarchy, interaction, system response, timing, focus, feedback, content, validation, errors, interruption, retry, cancellation, duplicate prevention, recovery, completion, post-task behavior, analytics, and acceptance evidence. Link each rule to approved sources and identify simulated or unresolved behavior.

## Guardrails

Do not invent APIs, policies, persistence, latency, component behavior, commercial rules, or failure handling. Route behavior changes to Design and outcome-affecting changes to Validate.
