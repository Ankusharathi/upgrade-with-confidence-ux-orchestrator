# Formulate UX Insights

## Goal

Explain what an evidence cluster likely means and why it matters without presenting interpretation as direct observation.

## Method

For each candidate insight:

1. State the evidence pattern using linked cluster, finding, and evidence identifiers.
2. State the interpretation separately from the evidence.
3. Identify plausible alternative explanations and contradictory evidence.
4. Explain the consequence for the approved problem-framing decision.
5. Set confidence from evidence quality, consistency, coverage, recency, variation, and limitations.
6. State the inference boundary and evidence needed to raise confidence.

## Rules

- An insight must explain a supported pattern; it is not a rewritten observation or a recommendation.
- Use participant language only when a traceable approved quotation exists; never write an invented representative quote.
- Do not generalize beyond the studied roles, contexts, populations, or evidence types.
- Do not convert an expert issue, synthetic signal, or stakeholder claim into a user insight.
- Preserve low-confidence insights as hypotheses when they remain decision-relevant.

## Output

Populate `insights` in `../templates/INSIGHT-SYNTHESIS.md` with evidence, interpretation, alternatives, implication, confidence, and inference limits.
