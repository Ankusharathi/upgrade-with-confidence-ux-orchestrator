# Skill: Evaluate Accessibility Validation

## Purpose

Evaluate specified accessibility behavior through applicable automated, manual, assistive-technology, user, and specialist evidence without claiming certification.

## Method

1. Map approved accessibility requirements to test methods, platforms, browsers, settings, assistive technologies, and accountable reviewers.
2. Check semantic structure, names and roles, keyboard operation, focus order and visibility, status announcements, errors, contrast, zoom, reflow, motion, target size, timing, and alternatives as applicable.
3. Record exact build or prototype limitations and distinguish code-capable tests from design-only inspection.
4. Link each observation to requirement, state, evidence source, environment, impact, and remediation owner.
5. Preserve results from disabled participants as user evidence without treating any participant as representative of all access needs.
6. Separate automated detections, manual findings, assistive-technology behavior, participant evidence, and specialist judgment.

## Guardrails

Do not infer conformance from automated tools, a visual review, a prototype, or a small sample. Report untested criteria and specialist review status explicitly.
