# Skill: Maintain Delivery Traceability

## Purpose

Preserve the chain from approved need and design through implementation rules, build evidence, QA, defects, decisions, changes, revalidation, acceptance, and completion.

## Required chain

`requirement -> design element -> validation criterion/result -> implementation rule -> acceptance criterion -> component/content/data/analytics dependency -> QA check -> evidence -> defect -> decision/change -> fix -> retest -> owner acceptance`

## Method

Use stable IDs and exact versions; preserve many-to-many links; report orphan requirements, specifications without sources, QA checks without criteria, defects without owners, changes without decisions, fixes without retest, and acceptances without authority. Never fill missing links by inference.
