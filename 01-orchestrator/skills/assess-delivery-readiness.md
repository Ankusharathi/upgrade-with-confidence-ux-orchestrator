# Skill: Assess Delivery Readiness

## Purpose

Determine whether the approved package is ready for implementation acceptance and UX workflow completion.

## Checks

Verify source approvals and versions; flow and state completeness; implementation behavior and acceptance criteria; content, component, token, asset, data, analytics, accessibility, privacy, security, legal, operational, and support ownership; feasibility status; QA plan and environments; defect and change disposition; revalidation; engineering-QA dependencies; known debt; accepted risks; UX-owner acceptance; and implementation-owner acceptance.

## Result

Classify `ready`, `conditional`, `not-ready`, or `uncertain`. The Deliver gate may pass only when the Handoff Package is approved, blocking UX defects are resolved, explicitly deferred, or accepted by authorized humans, required revalidation is complete, and both accountable owners accept the current version.
