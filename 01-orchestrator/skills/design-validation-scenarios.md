# Skill: Design Validation Scenarios

## Purpose

Create neutral, realistic tasks and scenarios that test the approved design criteria without teaching participants the intended solution.

## Method

1. Map each scenario to roles, context, criterion, flow, state, risk, and source design element.
2. Use plausible starting conditions, test data, permissions, account or segment variations, and end conditions.
3. Write neutral task prompts that describe a goal, not interface labels or steps.
4. Define observable completion, partial completion, failure, critical error, recovery, abandonment, and assistance rules.
5. Include consequential branches, errors, interruptions, timeout, recovery, confirmation, and post-task behavior where in scope.
6. Add non-leading probes, comprehension checks, confidence questions, and retrospective prompts.
7. Pilot the script and record any change before full execution.

## Guardrails

- Do not expose confidential data or request unnecessary personal information.
- Do not claim a task was tested unless a traceable session or source executed it.
- Do not alter success rules after observing results without recording a protocol deviation.

## Output

A scenario set with traceable prompts, coverage, data setup, measures, critical errors, moderator guidance, accessibility accommodations, and pilot status.
