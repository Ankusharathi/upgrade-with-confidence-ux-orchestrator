# Skill: Assess Release UX Readiness

## Purpose

Summarize whether the tested implementation is ready from a UX perspective while preserving engineering-QA and release-authority boundaries.

## Checks

Confirm build and environment versions, executed coverage, critical flows and states, content, accessibility, analytics, defect disposition, retest, changes, revalidation, accepted risks, untested scope, rollback or monitoring needs, and relevant engineering security, performance, integration, regression, and operational results.

## Result

Recommend `ready`, `conditional`, `not-ready`, or `blocked`. This is a UX readiness recommendation, not production release approval. The accountable UX, implementation, QA, product, and release owners retain their respective authority.
