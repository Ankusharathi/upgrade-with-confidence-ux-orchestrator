# Skill: Classify Validation Issues

## Purpose

Create consistent, decision-useful issue records and revision routes from validation evidence.

## Method

1. Describe the observed barrier, context, affected role or need, consequence, and recovery path without embedding an unsupported solution.
2. Link the issue to evidence sources, criteria, design elements, tasks, states, and requirements.
3. Assess severity using consequence, recoverability, task criticality, accessibility or compliance risk, scope, and observed frequency.
4. Record confidence separately from severity; limited frequency does not make a severe consequence minor.
5. Classify as blocking, major, moderate, minor, observation, or unresolved according to the project rubric.
6. Assign an accountable owner, recommended route, target artifact, remediation intent, and revalidation requirement.
7. Record duplicate, related, accepted, deferred, resolved, and verified states without deleting history.

## Routing

- report or protocol defect -> Validate;
- interaction, content, flow, or specification defect -> Design;
- invalid opportunity or problem framing -> Define;
- missing or contradictory evidence -> Discover;
- risk acceptance -> accountable human, never the agent.
