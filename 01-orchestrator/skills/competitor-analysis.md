# Competitor Analysis

## Goal

Understand how relevant products handle the same user task or design challenge without treating competitor choices as user needs or automatic best practice.

## Method

1. Define the decision, task, market, user or account context, and comparison boundaries.
2. Select a justified mix of direct competitors, adjacent alternatives, and useful benchmarks.
3. Apply the same task and comparison criteria to every product where access permits.
4. Record product, surface, market, account type, access level, source, and observation date.
5. Separate observable behavior from interpretation, cross-product pattern, opportunity, and recommendation.
6. Record inaccessible states, incomplete flows, personalization, experiments, and other comparison limitations.

Useful comparison lenses include entry and eligibility, navigation, information architecture, account and role context, task steps, decision support, pricing transparency, errors and recovery, accessibility, trust, confirmation, and post-task support.

## Rules

- Use current public or authorized access only; do not bypass authentication or access controls.
- Do not copy a competitor pattern without evidence that it serves this project's users and constraints.
- Absence from an observed flow is not proof that a capability does not exist.
- Do not rank products from impression alone; use explicit criteria and evidence.
- Competitor observations are market evidence, not direct evidence of user behavior or preference.

## Output

Create `../templates/COMPETITOR-ANALYSIS.md` and register each source in the Evidence Register.
