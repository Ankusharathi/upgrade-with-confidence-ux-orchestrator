# Skill: Plan UX QA

## Purpose

Define credible implementation-fidelity and experience-QA coverage before testing begins.

## Method

Map approved flows, states, roles, permissions, platforms, breakpoints, devices, browsers, data conditions, accessibility settings, analytics, accepted risks, and consequential behavior to QA checks, environments, test data, owners, evidence, entry criteria, exit criteria, and stop rules. Identify what engineering, security, performance, automation, accessibility, content, or data specialists must verify.

## Output

A versioned UX QA Plan that distinguishes planned, executable, executed, blocked, deferred, and not-applicable coverage. No build evidence means no executed QA claim.
